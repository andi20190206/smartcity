---

## 一、模块概述

资金管理模块覆盖车辆采购到销售全链路的资金流转，核心职责包括：合作款项（保证金）管理、授信额度管控、垫款、提现、以及额度的实时计算与风控提醒。

额度管理主体为 **车商级别**（非经销公司级别）。

---

## 二、核心概念

### 2.1 合作款项（原"保证金"，因合规更名）

- 由 **车商** 缴纳，不可直接动用，仅作为授信杠杆基数
- 缴纳时机：车商入驻时一次性缴纳
- 缴纳方式：线上转账（打入钱包子账户）或 线下打款后平台录入，两种并存
- 合作款项变动（追加/退还）需走审核流程

### 2.2 额度体系

所有额度以 **车商** 为主体计算：

| 字段 | 含义 | 计算方式 |
|------|------|----------|
| 代经销合作款项 | 合作款项余额 | 车商缴纳的保证金金额 |
| 已用合作款项 | 已消耗的保证金额度 | 具体公式待与业务确认 |
| 可用合作款项 | 保证金可用部分 | 合作款项 - 已用合作款项 |
| 最大额度 | 最高授信额度 | 合作款项 ÷ 30 × 100（杠杆比30:100） |
| 在途额度 | 已占用授信额度 | ∑ 已垫款未签注的车辆累计垫款金额 |
| 可用额度 | 剩余可用授信额度 | 最大额度 - 在途额度 |
| 可申请额度 | 本次可申请的最大垫款金额 | Min（可用合作款项额度, 可用额度） |

### 2.3 可用合作款项额度计算

```
可用合作款项额度 = 合作款项
    - 销售亏损（∑ 单台亏损金额，只计亏不计赚）
    - 存货占用（∑ 已签约未销售车辆采购合同价 × 30%）
    + 合作款项变动（追加/退还）
```

> ⚠️ 已用合作款项的完整公式待与业务负责人确认，上述为当前理解，可能有其他扣减项。

### 2.4 风控规则

- 可申请额度为负数时：允许显示负数，界面加红提醒
- 审批人可看到超额提示，但系统不强制拦截，由审批人判断是否通过
- 额度不足时仍可发起申请，审批环节把控风险

## 三、垫款

### 3.1 垫款规则

- 一台车支持 **多笔垫款**，分次申请
- 每笔垫款金额无限制
- 累计垫款总额 **不能超过采购合同金额**
- 发起垫款时显示：总金额（合同价）、可申请金额（合同价-已垫金额）、申请垫款金额（手动输入）

### 3.2 垫款触发时机（两种模式，可配置）

| 模式 | 说明 |
|------|------|
| 手动发起 | 采购审批通过、合同签署完成后，车商在小程序手动点击"发起垫款" |
| 自动进入 | 采购审批通过后系统自动创建垫款申请（待确认是否需要） |

### 3.3 垫款流程

```
发起垫款（输入金额）→ 垫款审批 → 审批通过 → 自动提现至卖方银行卡
```

### 3.4 垫款审批

- 审批节点可配置（通过审批中心统一管理）
- 资方为银行时，审批流程可能与经销公司自有资金不同（多个审批节点）
- 审批人可看到车商当前额度状态（含超额提醒）

### 3.5 垫款资金来源

| 资金来源 | 资金路径 | 说明 |
|----------|----------|------|
| 经销公司自有资金 | 经销公司钱包 → 卖方子钱包 → 卖方银行卡 | 经销公司直接出资 |
| 银行/资方 | 路径A：银行→经销公司→卖方 或 路径B：银行→直接打给卖方 | 路径待确认，需对接银行接口 |

## 四、提现

### 4.1 提现规则

- 垫款审批通过后 **立即自动提现** 至卖方对应银行卡
- 同时支持人工手动提现（提现方式为配置项）
- 银行卡信息已在创建子账户时验证，不存在卡号错误的情况

### 4.2 提现失败处理

| 失败原因 | 处理方式 |
|----------|----------|
| 提现额度限制 | 系统记录失败信息，通知相关人员处理 |
| 银行卡已注销 | 系统记录失败信息，通知相关人员更新收款信息 |
| 其他银行侧错误 | 返回银行报错信息，通知相关人员 |

### 4.3 提现失败通知

- 通知渠道：企微应用消息 + 短信
- 通知对象：车商 + 平台运营人员 + 提现发起人
- 通知内容：包含失败原因、订单信息、处理建议

## 五、合作款项变动管理

### 5.1 变动类型

| 类型 | 说明 |
|------|------|
| 线下合作款项 | 线下打款后平台录入 |
| 钱包合作款项 | 线上转账至钱包子账户 |

### 5.2 变动操作

| 字段 | 说明 |
|------|------|
| 变动类型 | 线下合作款项 / 钱包合作款项 |
| 变动方向 | 扣减 / 增加 |
| 金额 | 变动金额 |
| 变动原因 | 扣减钱包 / 扣减所有 / 追加缴纳 / 退还 等 |
| 变动凭证 | 需上传凭证图片 |

### 5.3 变动审核

- 审核主体：**平台** 审核（建议）
- 理由：车商与经销公司为合作关系，非上下级；平台掌握所有账户数据，适合统一审核
- 审核结果：通过 / 驳回（驳回后可重新发起）

## 七、签注与额度释放

- 签注 = 车辆转移待登记（将车辆登记转移至经销公司名下）
- 入库后即可办理签注
- 签注完成后：该车辆的垫款金额从 **在途额度** 中释放
- 释放后 **可用额度** 相应增加，车商可申请新的垫款

---

## 八、数据对象关系

```
车商额度（主表）
├── 合作款项记录
├── 合作款项变动记录（含审核状态、凭证）
├── 垫款记录（1:N，关联采购单/车辆）
│   ├── 垫款金额
│   ├── 垫款状态（待审批/审批中/已通过/已驳回）
│   └── 提现状态（待提现/提现中/已到账/提现失败）
├── 在途额度明细（已垫款未签注车辆清单）
└── 销售亏损记录（已完成销售且亏损的订单）
```

## 九、业务规则汇总

| 规则 | 说明 |
|------|------|
| 额度主体 | 以车商为主体，非经销公司 |
| 杠杆比 | 合作款项:最大额度 = 30:100 |
| 存货占用比例 | 30%（独立参数，非杠杆比） |
| 垫款上限 | 累计垫款 ≤ 采购合同金额 |
| 多笔垫款 | 允许分次申请，单笔无限额 |
| 负额度处理 | 允许显示负数，加红提醒，审批人把控 |
| 签注释放 | 签注完成后释放在途额度 |
| 提现时效 | 审批通过后立即执行 |
| 合作款项变动 | 需平台审核，上传凭证 |
